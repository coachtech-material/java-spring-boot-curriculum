## JShell とは（Java の対話実行環境）

**JShell** は、Java のコードを 1 行ずつ入力して即座に結果を確かめられる対話実行環境（REPL）です。Java 9 で導入されました。クラスや `main` メソッドを用意しなくても、`"5" + 3` のような式をそのまま打てば結果が返ります。

PHP の `php -a`（対話モード）や Laravel の `php artisan tinker` を使った経験があれば、その Java 版だと考えてください。本来 Java は 1-1-3 で見たように「クラスの中に書いてコンパイルして実行」する言語ですが、JShell はその手間を省いて、文法やライブラリの挙動を手早く試すための道具です。

💡 JShell はあくまで「お試し・確認」のための環境です。実際のアプリケーションは、Part 5 で学ぶように `.java` ファイルに書いてビルドします。1-1-3 で触れた「1 ファイル 1 クラス」「パッケージ ＝ ディレクトリ」といった規約は、JShell では扱いません（Part 5 で実ファイルとして体験します）。

## なぜ Docker で動かすのか

JShell を使うには JDK が必要です。ローカルに JDK を入れてもよいのですが、本教材ではあなたが習熟している Docker を使い、JDK 入りの公式イメージをそのまま起動します。これなら、自分のマシンに JDK をインストールせずに Java 21 を試せます。

使うイメージは `eclipse-temurin:21` です。これは技術スタックでも採用している Adoptium 公式の OpenJDK で、JShell を含む JDK 一式が入っています。Laravel で Sail（Docker）を使って PHP 環境を包んでいたのと同じ発想で、Java の実行環境をコンテナに任せるわけです。

## 🏃 実践: JShell を起動して Java に触れる

### 🏃 Step 1: JShell を起動する

ターミナルで次のコマンドを実行します。

```bash
docker run -it --rm eclipse-temurin:21 jshell
```

💡 このコマンドは、いま自分がどのフォルダにいても同じように動きます。ホストのファイルを読み書きしない（マウントしていない）ため、専用のディレクトリを作ったり、そこへ移動したりする必要はありません。ターミナルを開いて、そのまま実行してください。Laravel の `sail up` はプロジェクトのフォルダで実行する必要がありましたが、この JShell 起動はフォルダと無関係です（作業フォルダが要るのは、後述の「コードを残したいとき」だけです）。

各部分の意味は次のとおりです。

- `-it`: 対話モードで動かすための指定（入力を受け付け、画面に表示する）。JShell は対話環境なので必須です
- `--rm`: 終了時にコンテナを自動で片付ける（後片付け不要）
- `eclipse-temurin:21`: 使うイメージ（Java 21 入り）
- `jshell`: コンテナ内で起動するコマンド

初回はイメージのダウンロード（数百 MB）で少し時間がかかります。2 回目以降はすぐ起動します。起動すると、次のような表示が出ます。

```text
INFO: Created user preferences directory.
|  Welcome to JShell -- Version 21.0.11
|  For an introduction type: /help intro

jshell>
```

> 💡 1 行目の `INFO: Created user preferences directory.` は、JShell が設定用フォルダを作っただけのメッセージです。**無視して構いません**。`jshell>` というプロンプトが出ていれば、入力待ちの状態です（バージョン番号は時期により異なります。これは 2026 年 6 月時点の例です）。

### 🏃 Step 2: 最初のコードを実行する

`jshell>` の後ろに、次を打って Enter を押します。

```text
jshell> System.out.println("Hello, Java!")
Hello, Java!
```

PHP の `echo` にあたる `System.out.println` で、文字列が表示されました。次に、クラスも `main` も書かずに、式だけを打ってみます。

```text
jshell> "5" + 3
$1 ==> "53"
```

結果が `$1 ==> "53"` と表示されました。`$1` は JShell が結果に自動で付けた名前で、`==>` の右が値です（番号は入力した順に振られるため、手元では前後することがあります）。`"5" + 3` が `"53"`（文字列の連結）になる理由は 1-2-1 で詳しく扱います。今は「式を打つと即結果が返る」ことを体感できれば十分です。

### 🏃 Step 3: 静的型付けを「壊して」体感する

1-1-2 で、Java は静的型付けで「型の合わない代入はコンパイルの段階で弾かれる」と学びました。これを実際に起こしてみます。

```text
jshell> int n = 10
n ==> 10

jshell> n = "twenty"
|  Error:
|  incompatible types: java.lang.String cannot be converted to int
|  n = "twenty"
|      ^------^
```

`int` 型の `n` に文字列 `"twenty"` を入れようとすると、`incompatible types`（型が両立しない）というエラーになり、代入は実行されません。PHP なら何事もなく入ってしまっていたところを、Java は型が合わないと教えてくれます。これが 1-1-2 で学んだ静的型付けの手触りです。

💡 JShell は学習用のため、エラーが出ても止まらずに次の入力を受け付けます。気軽に「わざと間違えて、何と言われるか見てみる」ことができます。

### 🏃 Step 4: 知っておくと便利な操作

JShell には、`/` で始まる便利なコマンドがあります。

```text
jshell> /vars
|    int n = 10

jshell> /list
   1 : System.out.println("Hello, Java!")
   2 : "5" + 3
   3 : int n = 10;
```

- `/vars`: これまでに宣言した変数の一覧を表示する
- `/list`: これまでに入力したコードの一覧を表示する
- `/exit`: JShell を終了する（`--rm` を付けているので、コンテナも一緒に消えます）

メソッドやクラスのような複数行のコードも、そのまま貼り付けたり、改行しながら入力したりできます（Part 2 以降のハンズオンで実際に使います）。

> 💡 **コードを残したいとき**: `--rm` で起動したコンテナは、`/exit` するとコードも消えます。書いたコードを残して何度も使いたい場合は、手元に作業フォルダを作り、`.jsh` ファイルにコードを書いておいて読み込む方法があります。
>
> ```bash
> mkdir java-playground
> cd java-playground
> # この中に好きなエディタで playground.jsh を作成（例: VS Code なら code . で開く）
> docker run -it --rm -v "$PWD":/work -w /work eclipse-temurin:21 jshell
> ```
>
> 起動後、JShell の中で `/open playground.jsh` と打つと、ファイルに書いたコードを読み込めます。普段は Step 1 のシンプルな 1 行起動で十分なので、必要になったら使ってください。

確認が終わったら `/exit` で抜けます。

```text
jshell> /exit
|  Goodbye
```

## 以降のセクションでの使い方

Part 1〜2 の各セクションの末尾には、「🏃 手を動かす（任意）」という枠があります（このセクションと同じく **任意** です）。そこには、そのセクションで学んだ概念を確かめる短いコードが載っています。

使い方はいつも同じです。

1. Step 1 のコマンド（`docker run -it --rm eclipse-temurin:21 jshell`）で JShell を起動する
2. コードを試す。`jshell>` が付いた式は 1 つずつ入力し、`jshell>` の付かない `java` のブロック（クラス定義・`try` など複数行の 1 つのまとまり）は、選択してそのまま貼り付ける
3. 表示される結果を確かめ、終わったら `/exit` で抜ける

読み飛ばしても本筋の理解には支障ありません。「読んで分かったつもりだけど、本当にそう動くのか確かめたい」と思ったときに、ぜひ手を動かしてみてください。
