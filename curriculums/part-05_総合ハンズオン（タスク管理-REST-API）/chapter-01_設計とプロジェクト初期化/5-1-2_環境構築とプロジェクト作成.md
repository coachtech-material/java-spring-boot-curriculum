# 5-1-2 環境構築とプロジェクト作成

📝 **このハンズオンで使う機能**: `pom.xml` と Maven（3-1-2 で学習）・`application.yml` とプロファイル（3-1-3 で学習）・Docker（4-3-2 で学習）

## 🎯 このセクションで学ぶこと

- JDK 21・Docker・IDE（IntelliJ IDEA）を準備し、開発できる状態を整える
- Spring Initializr でプロジェクトを生成し、生成された `pom.xml` の依存を読み解ける
- MySQL を Docker Compose で起動し、`application.yml` でアプリから接続できる
- アプリを起動し、「正しく立ち上がった」ことを確認できる

準備の確認から始め、プロジェクト生成、`pom.xml` の読解、MySQL の起動、接続設定、起動確認へと進みます。

## 導入: 動く土台を最初に用意する

5-1-1 で設計図を引きました。次にやるべきは、いきなりエンティティを書くことではありません。**まず「空っぽだが起動する」プロジェクトを用意する** ことです。Laravel でも、新規プロジェクトを作って `sail up` で起動し、ブラウザでウェルカム画面が出るのを確認してから機能を作り始めたはずです。あの「動く土台ができた」という確認を、Java / Spring Boot でも最初に行います。

土台が動くと分かっていれば、この先の実装でエラーが出ても「原因は自分が今書いたコードだ」と切り分けられます。逆に土台が怪しいまま進めると、エラーが環境のせいかコードのせいか分からず、何倍も時間を溶かします。だからこのセクションは地味ですが、ハンズオン全体の土台として欠かせません。

### 🧠 先輩エンジニアの思考プロセス

> Java の環境構築は、Laravel より少しだけ確認することが多いです。JDK のバージョン、ビルドツール、IDE、DB。私は新しい案件に入るたび、まず `java -version` と `docker --version` を打って、想定どおりの版が入っているかを確認するクセがあります。Java は版の違いが文法レベルで効いてくるので、ここを曖昧にすると後で必ず詰まります。

> もうひとつ、最初に DB を Docker で立てておくのは強くおすすめします。ローカルに MySQL を直接入れると、案件ごとに版が違ってぶつかります。Docker なら案件ごとにコンテナを分けられて、`docker compose down` で綺麗に片付く。Laravel Sail で体感した「DB を汚さない」安心感を、Spring Boot でもそのまま持ち込めます。

## 🏃 実践: 起動可能なプロジェクトを用意する

### 🏃 Step 1: JDK 21 を用意する

Part 1〜2 では Docker の中の JDK（JShell）で Java を試していたので、ローカルには JDK を入れていませんでした。ここからは IntelliJ や `./mvnw` でビルド・実行するため、**ローカルに JDK 21 を導入** します。

まず、すでに入っているかを確認します。

```bash
# JDK のバージョン確認（21 であること）
java -version
```

`openjdk version "21..."` のように **21** が表示されれば、導入済みなので次に進みます。`command not found` や別の版（17 や 23 など）が出たら、JDK 21 を入れます。本教材は、無償で広く使われている **Eclipse Temurin 21** （Adoptium）を推奨します。

- **どの OS でも**: [Adoptium のダウンロードページ](https://adoptium.net/temurin/releases/?version=21) から OS 用のインストーラを入れる（最も確実）
- **macOS（Homebrew）**: `brew install --cask temurin@21`
- **Windows（winget）**: `winget install -e --id EclipseAdoptium.Temurin.21.JDK`
- **複数の Java を切り替えたい場合**: [SDKMAN!](https://sdkman.io/) を入れ、`sdk list java` で `21....-tem`（Temurin 21）を探して `sdk install java <その識別子>` を実行する

導入したら、**新しいターミナルを開いて** もう一度 `java -version` を実行し、**21** が出ることを確認します。Java は版の違いが文法・挙動に直結するので、ここで 21 に揃えておくことが後々の前提になります。

次に Docker を確認します（Part 1〜2 の JShell で使ったものをそのまま使います）。起動していなければ Docker Desktop を立ち上げてください。

```bash
docker --version
docker compose version
```

### 🏃 Step 2: Spring Initializr でプロジェクトを生成する

その前に、これから使う **Spring Initializr** について一言。Spring Initializr（[start.spring.io](https://start.spring.io/)）は、**Spring Boot プロジェクトの雛形をブラウザ上で生成してくれる公式ツール** です。ビルドツール・言語・Spring Boot のバージョン・使いたい依存（ライブラリ）を画面で選んで「GENERATE」を押すと、`pom.xml`・標準のディレクトリ構成・起動用のクラス・Maven ラッパー（`mvnw`）・`.gitignore` まで揃った、すぐビルドできる状態の ZIP がダウンロードされます。ゼロから手で用意する手間を省く、Spring Boot プロジェクトの定番の出発点です。

💡 **Laravel との対応**: `laravel new myapp` や `composer create-project laravel/laravel myapp` で新規プロジェクトの雛形を作ったのと同じ役割です。Laravel では CLI コマンドでしたが、Spring Initializr は **ブラウザの画面で依存を選んで生成する** のが特徴です（ターミナル派向けに `curl` でも生成できます。Step 2 末尾の 💡 を参照）。

では、[Spring Initializr](https://start.spring.io/) を開き、次のとおり設定します。

| 項目 | 値 |
|---|---|
| Project | **Maven** |
| Language | **Java** |
| Spring Boot | **4.0.x** （生成時点の最新パッチ。本教材は 4.0.6 を前提） |
| Group | `com.example` |
| Artifact | `taskapp` |
| Package name | `com.example.taskapp` |
| Packaging | **Jar** |
| Configuration | **YAML** （設定ファイルを `application.yml` 形式で生成する） |
| Java | **21** |
| Dependencies | **Spring Web** / **Spring Data JPA** / **Validation** / **Spring Security** / **Thymeleaf** / **MySQL Driver** |

💡 **ビルドツールと Java 版の確認**: Initializr の既定ビルドツールは Maven なのでそのまま使います（Gradle に変えません）。Java の既定値は時期により変わるので、生成前に **21 を明示的に選択** してください。

💡 **Configuration（Properties / YAML）とは**: Project Metadata の中にある **Configuration** は、生成する設定ファイルの形式を選ぶ項目です。既定は `application.properties` ですが、本教材は YAML 形式を使うので **YAML** を選びます。これで `src/main/resources/application.yml` が最初から生成され、あとで変換する手間が省けます（中身は Step 4 で書きます）。

「GENERATE」で ZIP がダウンロードされます。次に、この ZIP を **作業用ディレクトリ** に展開します。ターミナルで次を実行してください（`~/Downloads/taskapp.zip` の部分は、実際のダウンロード先に読み替えてください）。

```bash
# 作業用ディレクトリ（例: ~/dev）を用意し、その中にプロジェクトを展開する
mkdir -p ~/dev
cd ~/dev
unzip ~/Downloads/taskapp.zip        # taskapp/ ディレクトリが展開される
cd taskapp                           # 生成されたプロジェクトの中へ移動する
```

🔑 **これ以降のコマンドは、すべてこの `taskapp/` ディレクトリの中で実行します**。`docker compose ...` も `./mvnw ...` も、`compose.yaml` などのファイル作成も、この場所が基準です。

続いて、このプロジェクトを IDE で開きます。IntelliJ IDEA を起動し（未インストールなら [公式サイト](https://www.jetbrains.com/idea/download/) から無償の Community 版を入れておきます）、「Open」（既存プロジェクトを開く）から、いま展開した `~/dev/taskapp` フォルダを選びます。初回は Maven が依存ライブラリを取得し、プロジェクトのインデックス作成が走るので、完了まで数分待ちます。終わると、左の Project ツリーに `src/main/java` や `pom.xml` が見えます。プロジェクトの SDK が 21 になっているかは、File → Project Structure → Project で確認・設定できます。**以降、ファイルの作成・編集はこの IntelliJ で行います**。

> 💡 **コマンドで IDE を開きたい場合**: IntelliJ の CLI ランチャー（メニュー Tools → Create Command-line Launcher）を入れておくと、`taskapp/` の中で `idea .` と打つだけで開けます（VS Code の `code .` に相当します）。

> 💡 **ターミナルだけで生成したい場合**: ブラウザを使わずに ZIP を生成することもできます。`~/dev` ディレクトリで `curl https://start.spring.io/starter.zip -d type=maven-project -d language=java -d javaVersion=21 -d groupId=com.example -d artifactId=taskapp -d packageName=com.example.taskapp -d packaging=jar -d dependencies=web,data-jpa,validation,security,thymeleaf,mysql -o taskapp.zip` を実行して `taskapp.zip` を取得し、`unzip taskapp.zip` → `cd taskapp` と進めます（Spring Boot の版は Initializr の既定が使われるため、生成後に `pom.xml` の `<version>` が 4.0.x になっているかを確認してください）。本教材では、画面で内容を確かめられる Web UI を主として進めます。

生成された `pom.xml` の中身は次のようになります（主要部分の抜粋。`<name>` / `<description>` などのメタデータ要素は省略）。

```xml
<!-- pom.xml -->
<project xmlns="http://maven.apache.org/POM/4.0.0" ...>
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>4.0.6</version>
        <relativePath/>
    </parent>

    <groupId>com.example</groupId>
    <artifactId>taskapp</artifactId>
    <version>0.0.1-SNAPSHOT</version>

    <properties>
        <java.version>21</java.version>
    </properties>

    <dependencies>
        <!-- Web（Spring MVC・JSON・組み込み Tomcat） -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-webmvc</artifactId>
        </dependency>
        <!-- データアクセス（JPA・Hibernate・Spring Data JPA） -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-data-jpa</artifactId>
        </dependency>
        <!-- 入力検証（Bean Validation） -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-validation</artifactId>
        </dependency>
        <!-- 認証・認可 -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-security</artifactId>
        </dependency>
        <!-- テンプレートエンジン（画面描画） -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-thymeleaf</artifactId>
        </dependency>
        <!-- Thymeleaf と Security の連携 -->
        <dependency>
            <groupId>org.thymeleaf.extras</groupId>
            <artifactId>thymeleaf-extras-springsecurity6</artifactId>
        </dependency>
        <!-- MySQL ドライバ（実行時のみ） -->
        <dependency>
            <groupId>com.mysql</groupId>
            <artifactId>mysql-connector-j</artifactId>
            <scope>runtime</scope>
        </dependency>

        <!-- テスト（モジュールごとに分かれている） -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-webmvc-test</artifactId>
            <scope>test</scope>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-data-jpa-test</artifactId>
            <scope>test</scope>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-security-test</artifactId>
            <scope>test</scope>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-thymeleaf-test</artifactId>
            <scope>test</scope>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-validation-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>
```

3-1-2 で学んだとおり、依存にバージョンが書かれていないのは、親 POM（`spring-boot-starter-parent`）の BOM が版を一括管理しているからです。Spring Boot を `4.0.6` から上げれば、関連ライブラリの版が一斉に整合の取れた組み合わせへ揃います。

> 💡 **Part 3・4 で見た名前との違い**: 概念編では Web の土台を `spring-boot-starter-web`、テストを `spring-boot-starter-test` という名前で説明しました。Spring Boot 4 はスターターを機能ごとに細かく分ける方針になり、Spring Initializr は Web 用に `spring-boot-starter-webmvc`、テスト用に `spring-boot-starter-webmvc-test` などの **モジュール別スターター** を生成します。このうち `spring-boot-starter-web` は **非推奨** （当面は使用可）で、現場でよく出会う 3.x 案件ではこの旧名が主流です。一方 `spring-boot-starter-test` は廃止されたわけではなく存続しており、モジュール別テストスターターから推移的に取り込まれます（3.x ではこれを直接書きます）。**中身（Spring MVC・JUnit・Mockito・AssertJ・MockMvc など）は同じもの** なので、名前の違いとして押さえておけば十分です。

> 💡 **自動で入る `thymeleaf-extras-springsecurity6`**: Thymeleaf と Spring Security を両方選んだため、Initializr が連携ライブラリを自動追加しています。画面側で「ログイン中のユーザー名」を出すなど、テンプレートから認証情報を扱うためのものです（5-2-5 で必要なら使います）。名前に `6` と付きますが、Spring Security 7 でも動作します。

なお、JWT を扱う依存はまだ追加しません。認証を実装する **5-2-4 で、必要になった時点で追加** します（依存は「使うときに足す」のが、何のための依存かを見失わないコツです）。

### 🏃 Step 3: MySQL を Docker Compose で起動する

DB はローカルに直接入れず、Docker コンテナで動かします。先ほど `cd` した `taskapp/` の直下（`pom.xml` と同じ階層）に `compose.yaml` を作ります。

```yaml
# compose.yaml
services:
  mysql:
    image: mysql:8.4
    environment:
      MYSQL_DATABASE: taskapp
      MYSQL_USER: taskuser
      MYSQL_PASSWORD: secret
      MYSQL_ROOT_PASSWORD: rootsecret
    ports:
      - "3306:3306"
    volumes:
      - taskapp-mysql-data:/var/lib/mysql

volumes:
  taskapp-mysql-data:
```

起動します。

```bash
# MySQL コンテナをバックグラウンドで起動
docker compose up -d
# 起動を確認（mysql が "running" になっていること）
docker compose ps
```

💡 **Laravel との対応**: `sail up` に当たるのがこの `docker compose up -d` です。`MYSQL_DATABASE` / `MYSQL_USER` / `MYSQL_PASSWORD` は、Laravel の `.env` で `DB_DATABASE` / `DB_USERNAME` / `DB_PASSWORD` を決めていたのと同じ役割です。`volumes` を付けているので、コンテナを消してもデータは残ります。

### 🏃 Step 4: application.yml で接続設定を書く

Step 2 で **Configuration に YAML** を選んだので、`src/main/resources/application.yml` が生成されています。これを開いて、次を書きます。

> 💡 もし Configuration を選び忘れて `application.properties` になっていたら、`mv src/main/resources/application.properties src/main/resources/application.yml` でリネームすれば同じです（`.properties` を残したまま `.yml` を新規作成すると設定ファイルが 2 つになり紛らわしいので、リネームします）。

```yaml
# src/main/resources/application.yml
spring:
  application:
    name: taskapp
  datasource:
    url: jdbc:mysql://localhost:3306/taskapp
    username: taskuser
    password: secret
  jpa:
    hibernate:
      ddl-auto: update        # エンティティ定義からテーブルを作成・追従（開発用）
    show-sql: true            # Hibernate が発行する SQL をログに出す

server:
  port: 8080

logging:
  level:
    com.example.taskapp: debug   # 自分のアプリのログを詳しく出す（4-3-1）
```

`compose.yaml` で決めた DB 名・ユーザー・パスワードと、ここの `url` / `username` / `password` が一致している点を確認してください。`ddl-auto: update` は、エンティティ定義に合わせてテーブルを作る設定です（3-4-1 で学んだとおり、本番では `validate` などに切り替えます。仕上げの 5-3-2 で扱います）。

### 🏃 Step 5: アプリを起動して確認する

MySQL が起動している状態で（Step 3）、アプリを起動します。Initializr が生成した **Maven ラッパー** （`mvnw`）を使えば、グローバルに Maven を入れていなくても動きます。

```bash
# 組み込みサーバでアプリを起動する
./mvnw spring-boot:run
```

> 💡 **Windows の場合**: 先頭の `./` を外して `mvnw spring-boot:run` と実行します（PowerShell では `.\mvnw spring-boot:run`）。以降に出てくる `./mvnw ...` も、Windows ではすべて同様に読み替えてください。

この段階ではまだコントローラもエンティティも 1 つもありません。それでも、起動ログに次のような行が出れば **土台は完成** です。

```text
Tomcat started on port 8080 (http) with context path '/'
Started TaskappApplication in 3.2 seconds (process running for 3.9)
```

加えて、Spring Security を依存に入れたので、起動ログに次のような行も出ます（4-1-1 で触れた、自動生成される開発用パスワードです）。

```text
Using generated security password: 8e1a... (この値は起動のたびに変わります)
```

この行が出るのは、Spring Security が「まだ何も設定していないので、全部のエンドポイントを守る」という既定で動いている証拠です。独自のセキュリティ設定は 5-2-3 で書きます。

> ⚠️ **よくあるエラー**: MySQL コンテナを起動せずにアプリを起動すると、DB へ接続できず起動が失敗します。
>
> ```
> Communications link failure ... Connection refused
> ```
>
> **原因**: `application.yml` の `jdbc:mysql://localhost:3306/taskapp` に接続できていません（コンテナ未起動、またはポートの不一致）。
>
> **対処法**: `docker compose up -d` で MySQL を起動し、`docker compose ps` で稼働を確認してから、再度 `./mvnw spring-boot:run` を実行します。コンテナは初回起動時に初期化で数十秒かかることがあるため、起動直後に失敗したら少し待って再実行してください。

確認できたら、`Ctrl + C` でいったんアプリを止めます。

### 🏃 Step 6: Git で管理を始める

Initializr が生成したプロジェクトには `.gitignore` が含まれており、ビルド成果物の出力先 `target/` などが除外対象になっています（3-1-2 で触れた、Git の管理から外すべきディレクトリです）。リポジトリを初期化します。

```bash
# プロジェクト直下で Git リポジトリを初期化
git init
git add .
git commit -m "Spring Initializr で taskapp の雛形を作成"
```

これで、ここから先の実装を 1 コミットずつ積み上げていけます。

## ✨ まとめ

- 実装の前に、**空でも起動するプロジェクト** を用意する。これで以降のエラーを「自分のコードの問題」として切り分けられる
